全国の鉄道路線や公共交通機関を利用して遊ぶ、**2チーム対抗の大規模リアルタイム鬼ごっこ Web アプリケーション**です。  
プレイヤーはスマートフォンのブラウザからアプリのインストールやアカウント登録（メールアドレス不要）なしですぐに参加でき、管理者は専用ダッシュボードからゲーム進行、ルールパラメータ設定、ミッション配信、チーム行動監視、位置強制公開、スコア管理をリアルタイムに操作できます。

> **💡 Firebase Sparkプラン（完全無料版）対応:**
> クレジットカード登録が必要な有料プラン（Blaze）や Cloud Functions を一切排除し、**完全無料の「Firebase Sparkプラン」のみで本番運営できるサーバーレスアーキテクチャ**を採用しています。

## 🌟 主な特徴 & 注目機能

### 🚆 1. 駅・駅間走行区間・進行方向の自動サジェストシステム
GPS 座標から「今どの路線のどの駅、あるいはどの駅間にいるのか」を瞬時に自動判定し、マップ上部に提案カードを表示します。

```text
[ 駅構内・ホームにいる時 ]
📍 駅を検出 (約30m)
東京 (東海道新幹線 / JR山手線 他)  [設定] [他の候補▼]

[ 電車で走行中の時 ]
🚆 走行中の区間を推定 (線路から約20m)
JR山手線 渋谷〜恵比寿間 (次は恵比寿)  [設定] [他の候補▼]
⚡ 現在地の自動反映 [ オート ON ]
```

- **📍 駅ホーム・構内検出（AT_STATION）**: 駅中心から 250m 以内の場合、乗り入れ路線を含む駅名（例: `東京 (JR山手線 / 東海道新幹線 他)`）を最優先サジェスト。
- **🚆 駅間走行区間の推論（IN_TRANSIT）**: 電車走行中の場合、全国 8,988 駅の接続ネットワークと直交幾何計算により、線路沿い（600m以内）の走行区間（例: `JR山手線 渋谷〜恵比寿間`）を自動推定。
- **🧭 進行方向 & 次駅の自動判定**: 連続する測位ベクトルと線路の向きから進行方向を判定し、「次は恵比寿」のように次の停車駅を先回り表示。
- **⚡ オートチェックイン（自動反映モード）**: 移動に合わせて現在地が自動的に更新。GPS の一時的な測位ブレを防ぐ**2連続判定フィルター（デバウンス）**を搭載。
- **📶 オフライン PWA 完全対応**: 駅ネットワークデータは Service Worker により端末内にキャッシュ。地下や電波の弱い山間部でも数ミリ秒以内で推論が動作。

### 🎯 2. サバイバル制 vs ポイント交代制の柔軟な勝敗判定モード
管理画面からワンクリックで勝敗モードを切り替え可能です。
- **サバイバル制（SURVIVAL - デフォルト）**:
  - 逃走者側の勝利: 制限時間終了まで逃走者が1人でも生き残った場合。
  - 鬼側の勝利: 制限時間内にすべての逃走者を確保（全滅）させた場合。
  - 確保された逃走者はそのまま脱落（`CAPTURED`）となり、鬼に転向しない生き残り特化ルール（セキュリティルールによるアトミックな捕獲検証と脱落ステータスの不可逆固定）。
- **ポイント交代制（SCORE_SWAP）**:
  - 鬼が逃走者を捕獲すると **+50pt** が入り、即座に攻守が交代。制限時間終了時の累積チームスコアで勝敗を競うポイント争奪ルール。

### 🛡️ 3. 特例保護エリア（グリーン車 / 安全地帯）機能
- 移動手段や休憩スペースに応じた捕獲免責ステータスをプレイヤー自身で設定可能:
  - **🟢 特例: グリーン車（GREEN_CAR）**: 特急・新幹線・普通列車グリーン車などの着席移動中。
  - **🛡️ 特例: 安全地帯（SAFE_ZONE）**: 食事中、救護室、改札外の指定集合場所等。
- 保護エリアに滞在している間、相手チームの鬼は画面上の「捕獲」ボタンが無効化され、**Firestore Security Rules のトランザクション検証によって不正な強制捕獲も物理遮断**されます。

### 🚄 4. 新幹線乗車トラッカー（最長乗車制限 & 下車後待機）
長距離新幹線の連続利用によるゲームバランス崩壊を防止する自動タイマー機構です。
- 新幹線に乗車した際、「新幹線乗車開始」ボタンをタップすると乗車タイマーが作動。
- **最長乗車・区間制限**: 管理者設定時間（デフォルト150分、0〜600分 / 0=無制限）および連続区間数（デフォルト0=無制限、0〜50区間）を超えると警告を発出。
- **下車後ペナルティ待機**: 新幹線を下車すると自動的にクールダウン待機モード（デフォルト60分、1〜180分で設定可）へ移行し、連続利用による逃走の偏りを防ぎます。
- **誤操作防止・悪用抑止キャンセル**: 新幹線乗車開始から60秒以内かつ未移動（セグメント数0）の場合のみキャンセルが可能。乗車移動開始後の不正なタイマーリセットはセキュリティルールにより物理遮断されます。

### 👥 5. チーム同一行動監視（1.5km 離脱アラート）& 個別ペナルティ強制開示
- 各チームは原則として同一行動をとるルール（単独行動や別ルートによる挟み撃ちの禁止）。
- チームメンバー間の最大離脱距離が **1,500m** を超過した場合（有効期限内のスナップショットのみ判定）、プレイヤー画面および管理者ダッシュボードに**警告バナー**が表示されます。
- 管理者は単独行動を行ったプレイヤーに対し、**「🚨 個別ペナルティ強制開示」**を発動可能。管理者がペナルティフラグを設定すると、該当プレイヤーの端末が安全に自身の現在地スナップショット（`PENALTY` スコープ）を生成・公開し、相手チームのマップ上へ一定時間赤色ピンでピンポイント開示されます。

### 📡 6. 3種類のリニア位置開示システム
- **全体定期開示（GLOBAL_SNAPSHOT）**: 管理者のフェーズ移行や一定間隔で全員の位置スナップショットを開示。
- **チーム別開示（TEAM_SNAPSHOT）**: 逃走者または鬼の位置を戦略的に公開。
- **個別ペナルティ開示（PENALTY_SNAPSHOT）**: 同一行動違反やルール違反を犯した特定のプレイヤーのみをマップ上に赤色ピンでピンポイント開示。

### ⚙️ 7. 管理者リアルタイム可変設定パネル（8パラメータ）
管理画面からゲームを中断することなく、以下のパラメータをリアルタイムに変更できます:
1. **勝敗判定モード**: `サバイバル制 (SURVIVAL - デフォルト)` / `ポイント交代制 (SCORE_SWAP)`
2. **新幹線・特急 最長連続乗車時間**: 0〜600分（0=無制限、デフォルト150分）
3. **新幹線・特急 最長連続区間数**: 0〜50区間（0=無制限、デフォルト0=無制限）
4. **新幹線下車後待機義務**: 1〜180分（デフォルト60分）
5. **定期位置開示 間隔**: 5〜120分ごと（デフォルト30分）
6. **定期位置開示 継続時間**: 1〜30分間（デフォルト5分）
7. **捕獲後 待機時間**: 5〜120分間（デフォルト30分）
8. **ミッション不参加ペナルティ常時開示**: 1〜180分間（デフォルト60分）

## 🎮 プレイヤー向け遊び方ガイド

### 1. ゲームへの参加（メールアドレス不要・高セキュリティ）
1. 主催者から共有された URL（`/#/`）にアクセス、または管理画面から提示された **QRコードをスマホのカメラで読み取り** ます。
2. 初回参加は「**新規エントリー**」タブで以下を入力するだけです:
   - **ユーザーID**: 半角英数字4文字以上（例: `yamada01`。メールアドレスの入力は一切不要でプライバシー安心）
   - **パスワード**: 6文字以上
   - **ニックネーム**: ゲーム中に表示される名前
   - **所属チーム**: **Team A** または **Team B** を選択
3. 「ゲームに参加する」をタップすると即座にマップ画面へ移動します。
4. **中断・再開ログイン**:
   - スマホの充電切れや誤ってブラウザを閉じた場合、別端末へ引き継ぎたい場合も「**再開ログイン**」タブからユーザーIDとパスワードを入れるだけで即座に復帰できます。

### 2. マップ画面の操作
- **自分の現在地**: 青いピン（あるいはチームカラー）で表示されます。
- **現在地の設定**:
   - 駅や電車に乗ると、画面上部に**提案カード**が出現します。
   - **「設定」**をタップすると、自分の現在地ステータス（`lastStation`）が更新され、他の仲間や鬼にも伝わります。
   - **「⚡ 現在地の自動反映」**をタップして「オート ON」にしておけば、移動中にスマホを操作しなくても自動で更新されます。
   - 「他の候補」をタップすると、乗り入れ路線の別駅や近隣駅一覧から手動で選ぶことも可能です。
- **画面の常時点灯（Wake Lock）**:
   - マップを開いている間はスマートフォンの画面が自動消灯しないため、移動中も快適に確認できます。
- **高パフォーマンス・スムーズな位置追従**:
   - GPS位置が更新された際も地図キャンバス（Leaflet）を再生成せず、マーカー座標のみを差分追従させるため、ズームやドラッグ操作中のチラつき・視点リセットが一切発生しません。
- **特例保護エリアの申告**:
   - グリーン車着席時や休憩・飲食時は、画面上の保護バッジから「グリーン車」「安全地帯」を選択することで一時的に捕獲免疫を得られます。

### 3. ゲームの基本ルール
| 役割 | 目的・できること |
| :--- | :--- |
| **鬼（ONI）** | 逃走者を追跡し、接近したら画面の**「捕獲」**ボタンをタップして確保する。<br>捕獲に成功するとチームに **+50pt** が入り、ポイント交代制の場合は攻守が交代します。 |
| **逃走者（RUNNER）** | 鬼から逃げつつ、各地のミッションをこなしてスコアを稼ぐ。<br>危険な時は**「無敵カード」**を使って 30 分間捕獲を無効化できます。 |

- **無敵カード**:
  - 逃走者チームが使える強力な防御アイテムです。
  - 使うと **30分間**、鬼からの捕獲を一切受け付けなくなります（タイマーが画面に表示されます）。
- **待機モード**:
  - 捕獲後の待機（デフォルト30分、5〜120分で可変）または新幹線下車後の待機（デフォルト60分、1〜180分で可変）中、安全に一時離脱するステータスです。設定時間経過後に自動的にアクティブへ復帰します。
- **ミッション達成報告**:
  - 管理者から配信されるミッション（例:「○○駅の駅名看板を撮影せよ」「名物を購入せよ」等）を達成したら、ミッション画面から報告します。
  - 達成するとチームおよび個人にスコアが加算され、さらに **20% の確率で無敵カード**がボーナスとして手に入ります！
- **SOS（緊急通報） & リタイア**:
  - 体調不良、怪我、トラブルの際はいつでも「SOS」ボタンを押せます。
  - SOS を発信すると、現在地が管理者の専用緊急マップへ即座に送信され、運営スタッフが救護に向かえます。

## 🛡️ 管理者向け運営ガイド（専門知識不要・完全ノーコード）

管理者は専用画面から、プログラミングやデータベース操作を一切行わずに直感的なクリック操作だけでゲームを運営できます。

### 1. 管理画面へのアクセス & 初期セットアップ
- URL: `/#/admin` または `/#admin`（ブラウザのURL直接入力、ブックマーク、戻る/進む操作でも即座に管理者ビューを表示）
- **初回管理者セットアップ（1分で完了）**:
  - 初めて利用する際は「初回管理者セットアップ」をクリック。
  - 希望の**管理者ID**と**パスワード**（8文字以上）を入力するだけで、初回限定のセキュアなワンタイム初期化（Atomic Bootstrap）により、Firebaseコンソールを触ることなく管理アカウントが即時発行されます（2人目以降の自己昇格は自動的に完全ロックされます）。
- **ワンクリック・初期セットアップウィザード & 完全リセット**:
  - ログイン後、「🚀 初期セットアップウィザード（1クリック）」ボタンを押すだけで、セッション初期化と36件の標準ミッション登録が一瞬で自動完了します。
  - ゲームリセット時は、参加者のスコア・初期ロールだけでなく新幹線セグメント数、特例保護ステータス、ペナルティ開示、直前駅情報等も完全にクリーンアップされ、次回ゲームへ不整合を残しません。

### 2. リアルタイム・ルール調整パネル
- 管理画面内の「広域交通鬼ごっこ ルール規定設定（リアルタイム可変）」パネルから、勝敗判定モード（サバイバル制 / ポイント交代制）、新幹線利用制限、定期開示間隔・継続時間、捕獲後待機時間、ペナルティ開示時間の8つのパラメータをリアルタイムに変更できます。

### 3. チーム同一行動監視 & 個別ペナルティ発動
- チームメンバー間の最大離脱距離がリアルタイムに計算され、設定閾値（1.5km）を超えているチームには警告バナーが表示されます。
- ペナルティが必要なプレイヤーに対して「🚨 個別ペナルティ強制開示」を実行すると、管理者が非公開座標を直接触ることなく、端末側の自己投影フックが作動して相手チームへ安全に位置を開示できます。

### 4. 参加者への案内（QRコード & コピー機能）
- 画面上に**参加用QRコード**が自動生成されます。
- プロジェクターで投影したり、紙に印刷して提示するだけで参加者がスムーズにエントリーできます。
- 「参加URLをコピー」「LINE用案内文をコピー」ボタンで、チャットグループへの周知も1タップです。

### 5. イベント期間に合わせた柔軟なフェーズ運用（1日・2日両対応）
イベントのスケジュールに合わせてボタン1つでフェーズを切り替えられます。
- **1日イベントの場合**:
  - `DAY 1 開始` → 昼休憩時などは `一時中断` / `再開` → 終盤に `クライマックス開始（最終ミッション）` → `ゲーム終了（結果発表）`
- **2日イベントの場合**:
  - 1日目の終わりに `1日目終了` → 2日目の朝に `DAY 2 開始` → `一時中断` / `再開` → `クライマックス開始` → `ゲーム終了（結果発表）`
- 任意のタイミングで**「🔄 攻守交代」**を実行して鬼と逃走者を入れ替えることも可能です。

### 6. ノーコード・ミッションセンター
管理画面内のミッションセンターで、ミッションの配信・作成・承認を直感的に操作できます:
- **配信中ミッションの管理**: 現在発動中のミッション一覧、対象チーム、残り時間をリアルタイムに確認。
- **ミッションカタログ（36件の標準ミッション＋オリジナル）**:
  - カードの **「全員へ」「Team A」「Team B」** ボタンをタップするだけで、指定したチームに即時配信。
  - 「🎲 ランダム配信」でサプライズイベントも演出可能。
  - **「＋ 新規ミッション作成」**: タイトル、説明、獲得ポイント（pt）、制限時間（分）、カテゴリ（写真・移動・謎解きなど）を自由に入力して独自ミッションを追加・編集・削除できます。
- **手動達成承認・ポイント付与**:
  - 参加者から写真を見せてもらったり報告を受けた際、プレイヤーとミッションを選んで「承認してスコア付与」を押せば、即座にポイント加算＆無敵カード抽選が実行されます。

### 7. 緊急アナウンス配信（全員一斉通知）
- ゲーム中、天候急変やトラブル、重要連絡を全参加者へリアルタイム通知できます。
- 管理画面の「📢 全体緊急アナウンス配信」からメッセージを入力して送信するだけで、全プレイヤーの画面に即時トースト通知および最新情報として共有されます（最新タイムスタンプ管理により、ページリロード時の不要な再通知ループを自動抑止）。

### 8. 安全管理（持続型SOS緊急通報マップ）
- プレイヤーが「SOS」を発信すると、管理画面に赤色アラートと専用緊急マップが表示され、正確な緯度経度・最寄り駅を確認できます。
- **60秒心拍同期 & 二重投影保存**: SOS発信後は60秒ごとの自動心拍および測位時に `privateLocations` と `emergencyLocationProjections` がアトミックに同時更新されるため、救護班が現場に到着するまで位置情報が消失することなくリアルタイム追跡可能です。

## 📱 スマートフォンでの推奨設定（PWA）

本アプリは **PWA（Progressive Web App）** に対応しています。ホーム画面に追加することで、アドレスバーのない全画面ネイティブアプリ感覚で遊ぶことができます。

- **iPhone / iPad (Safari)**:
  1. Safari でアプリの URL を開きます。
  2. 画面下部の中央にある **共有ボタン（四角から矢印が出ているアイコン）** をタップ。
  3. メニューから **「ホーム画面に追加」** を選択します。
- **Android (Chrome)**:
  1. Chrome でアプリの URL を開きます。
  2. 画面右上の **メニューボタン（縦の3点リーダー）** をタップ。
  3. **「ホーム画面に追加」** または **「アプリをインストール」** を選択します。

## 🏗️ システム構成と無料運用の仕組み

本アプリは **Firebase Spark プラン（完全無料）** の枠内で動作するように極限まで最適化されています。

```text
[ プレイヤー / 管理者端末 (PWA) ]
  │
  ├─ 全国駅・路線幾何推論エンジン (クライアント完全完結 / 8,988駅 / オフライン対応)
  │    ├─ 最寄り駅判定 (AT_STATION: 250m以内)
  │    ├─ 駅間線分直交判定 (IN_TRANSIT: 600m以内)
  │    └─ 進行方向ベクトル計算 (内積・コサイン類似度)
  │
  ├─ チーム同一行動監視エンジン (クライアント完結)
  │    └─ メンバー間最大離脱距離計算 (Haversine 幾何) & 1.5km 警告
  │
  ├─ GPS通信量スロットリング (BaaSクォータ保護)
  │    └─ 30m移動 / 60秒経過 / 5分生存心拍のみ Firestore へ書き込み
  │
  └─ クライアントサイド トランザクション (runTransaction)
       ├─ 捕獲処理（勝敗モード判定・特例保護エリア検証・30分待機・無敵カード付与・スコア加算）
       ├─ 無敵カード発動
       └─ ミッション達成記録

[ Cloud Firestore (無料枠: 1日5万回読み取り / 2万回書き込み) ]
  └─ 堅牢化セキュリティルール (firestore.rules)
       ├─ 初回1名限定アトミック管理者ブートストラップ（/system/admin_bootstrap）＆自己昇格ロック
       ├─ ゼロトラスト位置公開・ペナルティ自己投影（管理者の他者非公開座標直接アクセス/書込み物理遮断）
       ├─ 特例保護エリア（GREEN_CAR / SAFE_ZONE）の捕獲トランザクション物理遮断
       ├─ サバイバル制における捕獲状態不可逆保護（脱落プレイヤーのアトミック固定）
       ├─ ミッション達成スコアのリプレイ攻撃防止（完了ドキュメントとの厳格な排他トランザクション検証）
       ├─ 参加者によるユーザードキュメント自己削除（脱落・ペナルティ逃れ）の完全遮断
       ├─ 進行中フェーズ & 配信中ミッション厳格判定（未配信ミッションの不正クリア完全遮断）
       ├─ 監査ログ改ざん・全消去（[]）・縮退・巨大文字列DoSの物理阻止
       ├─ 新幹線不正キャンセル・待機短縮の物理阻止（開始60秒以内かつ0セグメント限定キャンセル）
       ├─ 捕獲トランザクションの改ざん防止（動的待機上限・開始ロック対応）
       ├─ SOSプロジェクションの有効期限上限（3分以内）
       ├─ 参加者および管理者のみに閲覧を絞ったBOLA保護（未参加アクセスの遮断）
       ├─ 同一チーム同士の捕獲を物理遮断
       ├─ スコア改ざん・無敵カード不正付与の完全遮断
       └─ プレイヤープライベート座標の秘匿 (privateLocations/{uid})

[ Hosting & Web セキュリティ (firebase.json) ]
  └─ 包括的HTTPセキュリティヘッダー
       ├─ Content-Security-Policy (CSP) による外部スクリプトインジェクション防御
       ├─ X-Frame-Options: DENY (クリックジャッキング対策)
       ├─ X-Content-Type-Options: nosniff (MIMEスニッフィング抑止)
       ├─ Referrer-Policy: strict-origin-when-cross-origin
       └─ Permissions-Policy (カメラ・位置情報等の最小権限ポリシー)
```

## 🚀 自動リリースパイプライン (CI/CD)

GitHub Actions を利用した**タグプッシュ連動の全自動リリースワークフロー**が構築されています。

1. **トリガー条件**:
   - `v*.*.*` 形式の Git タグ（例: `v1.1.0`）がプッシュされた時。
2. **自動実行ステップ**:
   - Node.js 環境セットアップ & 依存関係インストール (`npm ci`)
   - 静的解析・リンター (`npm run lint` - Biome)
   - 型チェック (`npm run typecheck` - TypeScript strict)
   - 単体テスト全件実行 (`npm test` - 267 テスト)
   - Firestore セキュリティルール & 統合テスト実行 (`npm run test:rules`, `npm run test:integration` - 計 30 テスト)
   - 本番ビルド検証 (`npm run build` - PWA アセット生成)
   - 脆弱性監査 (`npm audit --omit=dev`)
   - 直前タグからのコミットログ自動抽出 & GitHub Release 発行（タグ名・リリースノート・tgzソースアーカイブ自動添付）

## 🛠️ 開発者向けガイド

### ディレクトリ構成（クリーンアーキテクチャ準拠）
- `src/game/`: 純粋ドメインロジック（役割・フェーズ・捕獲・位置公開・新幹線/待機ライフサイクル・駅推論・チーム離脱計算・自動投影判定）
- `src/application/`: ユースケースとポート定義（Firestore や UI から独立したアプリケーションサービス）
- `src/infrastructure/`: Firebase クライアント、トランザクションゲートウェイ、差分購読サブスクライバー、心拍同期
- `src/hooks/`: React カスタムフック（認証状態、マップタイマー、位置監視、自動投影、Wake Lock、オンライン監視）
- `views/`: 画面ビュー（`MapView.tsx` + `views/map/*`、`AdminView.tsx` + `views/admin/*`、`MissionView.tsx`、`SetupView.tsx`）
- `tests/`: 単体テスト（Node native test runner + Vite SSR コンポーネント検証）、Firestore ルールテスト、エミュレータ結合テスト

### 必要環境
- **Node.js**: `v22` 以上（LTS 推奨）
- **npm**: `v10` 以上
- **Java**: `JDK 21`（Firebase Emulator 実行時）

### ローカル起動 & 検証コマンド
```bash
# 依存関係のインストール
npm ci

# 開発サーバー起動 (http://localhost:3000)
npm run dev

# 型チェック (TypeScript strict)
npm run typecheck

# 静的解析・Lint (Biome)
npm run lint

# 単体テストの実行 (全267テスト)
npm test

# Firestore セキュリティルールのエミュレータ検証 (全28テスト)
npm run test:rules

# トランザクション & ペイロード結合テスト (全2テスト)
npm run test:integration

# 本番依存の脆弱性監査
npm audit --omit=dev

# 本番ビルドの確認 (PWA Service Worker生成)
npm run build
```

### デプロイ手順（初回のみ）
1. [Firebase Console](https://console.firebase.google.com/) で無料プロジェクトを作成（Sparkプラン）。
2. Authentication で「匿名認証」と「メール/パスワード認証」を有効化。
3. Firestore Database を作成（東京リージョン `asia-northeast1` 推奨）。
4. `.env` に取得した Firebase API キー等を設定。
5. デプロイ実行:
   ```bash
   npx firebase login
   npx firebase use your-project-id
   npx firebase deploy
   ```
